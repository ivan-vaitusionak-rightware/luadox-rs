# The LuaLS renderer — executable specification

What `luadox -r luals` writes, rule by rule, so Phase 3 can be implemented against this
document instead of against `render/luals.py`.

**Authority.** The oracle is the clone at `<repo>/oracle` — `origin/luals-all` plus
`oracle-patches/`, built as the repository README describes. Every rule below was read
out of `luadox/render/luals.py` (422 lines) at that commit **and** confirmed against a
fixture under `spec/fixtures/`, except where the rule is marked *unverified*. Where this
document and the oracle disagree, the oracle wins and this document is wrong — say so
rather than matching the document.

**The oracle moves.** It gained a sixth patch during the writing of this spec. The
fixtures record the commit they were generated from in
`spec/fixtures/expected/provenance.json`; check it before trusting a byte here.

**Scope.** This is the renderer only. It takes the IR the prerender stage produces and
writes one file. What the IR *contains* — how `@within` chooses a collection, how a
symbol becomes a name — belongs to the Phase 2 contract; §2 lists only the IR fields this
renderer reads, so that a mistake upstream is visible as a wrong input rather than as a
wrong rule here.

---

## 1. The output as a whole

### LS-1.1 One file

The renderer writes exactly one file and copies nothing. `render(toprefs, dst)`:

| `dst` | file written |
|---|---|
| empty / `None` | `./luadox.lua`, after `log.warn('"out" is not defined in config file, assuming %s', dst)` |
| an existing file | that path, whatever its name |
| anything else not ending in `.lua` | `<dst>/luadox.lua` |
| anything else ending in `.lua` | that path |

The parent directory is created with `makedirs(..., exist_ok=True)` when it does not
exist. The test is `if not os.path.isfile(dst) and not dst.endswith('.lua')`, so a
*directory* named `defs.lua` satisfies the extension half, is left alone, and the run
then dies opening it. (*Unverified* — no fixture creates a directory with a `.lua` name.)

### LS-1.2 The header

The first lines are always, in order:

```
---@meta
-- Lua API definitions generated by LuaDox <version>.
-- <title>                                   ← only when a title exists
-- This file is generated. Do not edit.
                                             ← one empty line
```

`<version>` is `luadox.version.__version__`, `2.0.0dev0` at the pinned oracle. `<title>`
is `project.title`, falling back to `project.name`; when neither is set the line is
omitted entirely and the header is three lines.

### LS-1.3 The injected-globals block

Emitted only when the `[luals] globals` config value is non-empty, immediately after the
header's blank line:

```
-- Globals injected into the script execution environment.
---@type <mapped type>
<name> = nil
---@type <mapped type>
<name> = nil
                                             ← one empty line, after the last entry
```

The value is split by `files_str_to_list` — `shlex.split` per line, so tokens are
whitespace-separated and quotable across several indented lines. Each token is
`name[:type]`; `name.partition(':')` takes everything after the first colon as the type,
and an absent or empty type becomes `any`. The type goes through `_map_type` (§5) like
any other.

`name` must match `[A-Za-z_]\w*(\.[A-Za-z_]\w*)*`. If it does not, the run **exits 1**
after `log.critical('invalid [luals] globals token "%s": expected name[:type]', tok)`;
nothing is written. The parse context is cleared (`ref=None, file=None, line=None`)
before the block is emitted, so a diagnostic raised while mapping a global's type carries
no file or line.

> `luals_config`: `globals = app:Application env` produces
> ```
> -- Globals injected into the script execution environment.
> ---@type Application
> app = nil
> ---@type any
> env = nil
> ```

### LS-1.4 The namespace-stub block

After every topref has been emitted, the renderer scans **its own output lines** and
declares a table for any root that is used but never declared:

- a line matching `^([A-Za-z_]\w*) = ` **or** `^function ([A-Za-z_]\w*)\(` *declares*
  group 1;
- a line matching `^(?:function )?([A-Za-z_]\w*)[.:]` *uses* group 1 as a root;
- `stubs = sorted(used_roots - declared)`, sorted as plain strings.

When `stubs` is non-empty, this block is inserted at `lines.index('') + 1`, i.e.
immediately after the **first** empty line in the output — which is the header's, so the
block precedes the injected globals when both are present (*unverified*: no fixture has
both):

```
-- Namespace tables for members declared under them.
<name> = {}
<name> = {}
                                             ← one empty line
```

When there is no empty line at all in `lines` the block is appended at the end; that
cannot happen while the header emits one.

> `module_globals`: `log.write` and `log.level` use the root `log`, nothing declares it,
> so `log = {}` is emitted under the comment. `ping` is declared by
> `function ping() end`, and `answer` by `answer = nil`, so neither is a stub.

### LS-1.5 The final write

```python
f.write('\n'.join(lines) + …)      # conceptually
```

is really `'\n'.join(lines).rstrip() + '\n'`: every trailing blank line collapses into
exactly one final newline. The file is opened with `encoding='utf-8'` in **text mode**,
so on Windows every `\n` becomes `\r\n`. See *Line endings* in `html.md` — the same rule,
the same recommendation, and the reason the fixtures store LF.

## 2. What the renderer reads

Only these IR members are consulted. Anything else in the IR is invisible to this
renderer, which is the shortest description of §7.

| member | used for |
|---|---|
| the topref's class | `ClassRef` / `ModuleRef` / anything else selects the block form (§3.1); `type` and `symbol` are read by the *prerenderer*, to sort |
| `topref.name` | the `---@class` name and the assignment target |
| `topref.implicit` | whether a module gets a backing table (§3.3) |
| `topref.userdata['empty']` | the skip test (§3.1) |
| `topref.content` | the block's doc comment |
| `topref.flags['inherits']` | parents (§6) |
| `topref.collections` | the emission order of members (§3.2) |
| `col.heading`, `col.content`, `col.name` | a `@table`'s doc comment and name (§3.4) |
| `col.fields`, `col.functions` | members, in that order (§3.2) |
| `ref.content`, `ref.meta`, `ref.types` | a field's doc comment and type (§4.1) |
| `ref.symbol`, `ref.name`, `ref.scope` | a field's assignment target (§4.1) |
| `ref.params`, `ref.returns` | a function's annotations (§4.2) |
| `parser.refs_by_id` | `@see` names and the mixin-phrase lookup |
| `parser.resolve_ref` | type-name resolution (§5) |
| `parser.diagnostics` | the two categories this renderer raises (§8) |
| `config` | `[luals] globals`, `mixin_suffix`, `mixin_doc_phrase`; `project.title`/`name` |

Note what is **not** there: `ref.value`, `ref.display`, `ref.title`, `col.compact`,
`col.level`, `flags['since']`, `flags['deprecated']`, `flags['enum']`,
`flags['fullnames']`, `flags['order']`. The comment on `FieldRef.value` in
`reference.py` claims it exists for "the luals renderer's `@enum` emission" — at the
pinned oracle **there is no such emission** and the field is unread here (§7.1).

## 3. Top-level blocks

### LS-3.1 Which toprefs, in what order

`Prerenderer.process()` hands the renderer a list already sorted by
`(ref.type, ref.symbol)` — the **symbol**, after `@rename` has been applied, not the
display name. Types sort as plain strings: `class` < `manual` < `module`.

The renderer then walks that list and, for each topref:

1. skips it when `topref.userdata['empty'] and topref.implicit` — see §9.2, this is
   believed dead;
2. emits a class block for a `ClassRef` (§3.2);
3. emits a module block for a `ModuleRef` (§3.3);
4. **skips everything else.** `ManualRef` falls off the end of the `if/elif` with no
   output at all: manual pages produce nothing in a LuaLS definition file.

> `inherits_multi` emits `Base`, `Derived`, `Middle`, `Mixin` — alphabetical by symbol,
> so `Derived` precedes the `Middle` it inherits from. Order carries no meaning to the
> language server, and the renderer makes no attempt to emit a parent first.

> `manual`: `luadox.lua` contains the class `Doc` and nothing from `manual.md`.

### LS-3.2 A class

```
<doc comment>                                ← §4.3, omitted when the content is empty
---@class <name>[ : <parent>[, <parent>…]]
<name> = {}
                                             ← one empty line
<collections>
```

`<name>` is `topref.name`; `@display` is not consulted. Parents come from §6; the ` : `
and the `, ` between names appear only when there is at least one parent.

Then, for each entry of `topref.collections` in order:

- a `TableRef` → the table block of §3.4;
- anything else (the class's own self-collection, and every `@section`) → its members
  emitted directly, with no heading, no marker and nothing to say which collection they
  came from (§3.5).

> `naming`: `@display The Shell` does not change `---@class Shell`.

### LS-3.3 A module

An **explicit** module (`@module`):

```
<doc comment>
<name> = {}
                                             ← one empty line
<collections>
```

There is **no `---@class`** for a module, so a module name is a table and not a type.

An **implicit** module — one invented for a file that has documented elements but no
`@module` — emits neither the doc comment nor the assignment: its collections follow the
header directly, and the module's own doc comment, if the file had one, is **lost**.

> `explicit_module`: `gfx = {}` carries `---Graphics helpers.` and no `---@class`.
> `module_globals`: no line mentions the module at all.

### LS-3.4 A `@table` collection

```
<doc comment>                                ← heading first, then content (§4.3)
---@class <col.name>
<col.name> = {}
                                             ← one empty line
<members>                                    ← §3.5
```

Three things here are easy to get wrong:

1. **`col.name` is the bare `@table` name.** A table declared inside a class is *not*
   qualified by it: `@table Colors` inside `@class Palette` emits `Colors = {}` and
   `Colors.Primary = nil`, never `Palette.Colors`.
2. **Nesting is flattened.** A table inside a table is a separate entry in the same flat
   `collections` list, so it is emitted *after* the outer table's members, at the same
   level.
3. **The heading is the popped first sentence, without its period.** The prerender stage
   pops the leading sentence of a non-class/module collection into `col.heading` and
   `get_first_sentence` returns the text *before* the `.`, so the doc comment's first line
   ends without one. When the content had no sentence to pop, the heading falls back to
   `col.name`.

> `nested_table` emits, in order: `Palette`, `Colors` + `Colors.Primary` +
> `Colors.Secondary`, then `Accents` + `Accents.Warm`. The first doc line is
> `---Named colour slots` — no period.

### LS-3.5 Members of a collection

`_emit_members` emits **all fields first, then all functions**, each in the collection's
own order (which is the IR's `@order`/`@within` result, not source order). There is no
grouping, no blank-line separator beyond the one each member emits itself, and no marker
for the collection boundary.

The `default_type` argument is `'any'` at every call site.

> `xrefs`: the field `Link.target` is emitted before the function `Link.get`, though the
> function is declared first in the source.

## 4. Members

### LS-4.1 A field

```
<doc comment>                                ← content lines, then the @meta line
---@type <type>
<lhs> = nil
                                             ← one empty line
```

- The doc comment is `_content_to_lines(ref.content)` (§4.3) with, when `ref.meta` is
  set, one further line `*<meta>*` — the meta text with `luadox:` links stripped,
  wrapped in single asterisks. Because the content's own trailing blank line (§4.4) is
  still in the list at that point, the meta line is separated from the description by a
  blank `---`.
- `<type>` is `_map_type(ref.types)` when `@type` was given, and `any` otherwise.
- `<lhs>` is `ref.symbol` when the field's immediate scope is an **implicit** module,
  and `ref.name` in every other case. That is the only place the two can differ: a bare
  global in an implicit module has an unqualified symbol but a module-qualified name.
- The value is **always `nil`**, whatever the source assigned.

> `module_globals`: `answer = 42` in the source becomes `answer = nil`, while
> `log.level` keeps its path.
> `within_order`: `@meta read-only` produces
> ```
> ---Declared second, ordered first by default.
> ---
> ---*read-only*
> ---@type any
> ```

### LS-4.2 A function

```
<doc comment>
---@param <name> <type>[ <description>]      ← one per parameter, in signature order
---@return <type>[ # <description>]          ← one per @treturn
function <symbol>(<names>) end
                                             ← one empty line
```

- Parameters come from `ref.params`, which the prerender stage builds from the
  **signature**, not from the tags: every parameter in the source appears, in source
  order, with the types and description of its `@tparam` if there is one and with an
  empty list and empty content if there is not. A `@tparam` for a parameter that is not
  in the signature is dropped by the prerenderer and never reaches here.
- An untyped parameter renders as `any` (via `_map_type([])`) and raises a diagnostic
  (§8.2).
- The parameter description is `_inline(doc)` (§4.5) and is appended after a single
  space; when it is empty the line ends after the type.
- The return description is appended after `' # '` — the LuaLS marker separating a
  return's type from its description. Parameters use a plain space; returns use ` # `.
- **With no `@treturn` at all, exactly one `---@return any` is emitted.** The renderer
  never emits a zero-return function, because an empty body would make the language
  server infer `nil` and reject `local x = obj:create()`.
- The definition line uses `ref.symbol`, so a method keeps its colon
  (`function Widget:move(x, y) end`) and a function written as `Shell.make` keeps its
  dot even when it is emitted inside another class's block.
- The parameter list is `', '.join(name for name, _, _ in ref.params)`.

> `class_basic`: two `@treturn` produce two `---@return … # …` lines; `Widget.reset`
> with none produces `---@return any`.

### LS-4.3 A doc comment

`_emit_doc(lines)` is the only way a comment reaches the output:

1. pop leading lines whose `.strip()` is empty;
2. pop trailing ones likewise;
3. emit `'---' + line` for a line with content, and exactly `'---'` for a line that is
   empty or whitespace-only.

There is no wrapping, no re-indenting, no escaping and no length limit: a content line
is passed through byte-for-byte after the `---`. A line that already begins with `-`
simply concatenates — a snippet's own `-- comment` becomes `----- comment`.

> `code_snippets`: the snippet file's first line `-- A snippet file pulled in by …`
> appears as `----- A snippet file pulled in by …`.

### LS-4.4 Content to lines

`_content_to_lines(content)` walks the content fragments in order:

| fragment | lines produced |
|---|---|
| `Markdown` | `_strip_links(md.get()).split('\n')` — every line of the markdown, links reduced to their text |
| `Admonition` | `**<title>**`, then the admonition's own content recursively |
| `SeeAlso` | `See also: <name>, <name>…` — one line, `', '.join`, **omitted entirely when the fragment carries no ids** |

- An admonition's title is `_strip_links(elem.title)` when it has one, and
  `elem.type.title()` otherwise (`Note`, `Warning`, `Deprecated`). In practice the title
  is already filled in by the parser, which defaults it to the tag name capitalised.
- The admonition's body is flattened to the same indentation level as everything else:
  the nesting that produced it is not preserved, and no blank line separates the title
  from the body or the body from what follows.
- `SeeAlso` names come from `parser.refs_by_id.get(refid)`; a miss falls back to the raw
  id string, which cannot happen for ids the parser itself produced. An `@see` naming
  only unresolvable references produces an empty id list and therefore no line at all —
  where the html renderer still emits `<div class="see">See also </div>`.
- **Every content block ends with one empty line.** `parse_raw_content` walks the block's
  lines followed by a sentinel row `(-1, '', None)`, which appends an empty line to the
  block's last `Markdown` fragment — creating one after the last fragment when the block
  ended with a tag. The extra line is invisible at the end of a comment (`_emit_doc`
  trims it) and visible in the middle (the `@meta` case in §4.1).

`_strip_links` is `re.sub(r'\[([^\]]*)\]\(luadox:[^)]*\)', r'\1', md)`: it removes only
the `luadox:` links the prerender stage generated. Ordinary markdown links, emphasis,
fences, headings and raw HTML are passed through untouched — a LuaLS doc comment is
markdown and the language server renders it as such.

> `xrefs`: `@{Link.target}` → `Link.target`; `@{Link.target|a renamed target}` →
> `a renamed target`; `` `Link.target` `` → `` `Link.target` `` (the backticks are inside
> the link text, so they survive); an unresolvable `@{NoSuchThing}` was already reduced
> to plain text upstream and reaches here as `NoSuchThing`.

### LS-4.5 Inline content

`_inline(content)` — used for `@param` and `@return` descriptions, which must be one
line — is `' '.join(_content_to_lines(content))` with `\s+` collapsed to a single space
and the result stripped. An admonition inside a parameter description therefore becomes
`**Note** body text` on the same line, and a code fence becomes an unreadable one-liner
(*unverified*: no fixture puts a fence in a `@tparam`).

## 5. Types

`_map_type(types: List[str]) -> str` is the whole type system.

### LS-5.1 The algorithm

For each entry of the list, split on `|` and, for each non-empty trimmed part, in this
order:

1. **`::` in the part** → raise a `types` diagnostic
   (`type name "<part>" uses C++ scope syntax; use "."`) and append the part verbatim.
2. **The part is a key of `TYPE_MAP`** → append its value.

   | LuaDox | LuaLS |
   |---|---|
   | `bool` | `boolean` |
   | `int` | `integer` |
   | `float` | `number` |
   | `double` | `number` |
   | `void` | `nil` |

3. **`parser.resolve_ref(part)` returns a `ClassRef` or a `TableRef`** → append
   `ref.name`. Resolution is relative to the current context (`self.ctx.ref`, set by the
   caller to the element being emitted), so an unqualified name resolves the way a cross
   reference would. A ref that resolves to a *field* or *function* of that name is
   ignored, so a member cannot hijack a type position.
4. **Otherwise** → append the part verbatim, and raise a `types` diagnostic
   (`type name "<part>" does not resolve to a documented class or table`) when it is not
   in `LUALS_BUILTIN_TYPES` **and** it matches `[A-Za-z_][\w.]*`. The second condition
   silences table-literal and function types like `string[]` or `fun(x): number`, which
   are legal LuaLS and are passed through unreported.

   `LUALS_BUILTIN_TYPES` = `any boolean string number integer function table thread
   userdata lightuserdata nil unknown self`.

The parts are joined with `|`. An empty result — an empty list, or a list of empty
strings — yields `any`.

### LS-5.2 Where the types come from

`ref.types` on a field is `flags['type']`, i.e. the `@type` tag. On a parameter and a
return it is the `@tparam`/`@treturn` type list, which the tag parser has already split
on `|`. So `@tparam string|nil x` arrives as `['string', 'nil']` and `_map_type` splits
again on a `|` that is no longer there — both paths converge on `string|nil`.

### LS-5.3 The html renderer does not do this

`render/html.py` prints type names verbatim (linking the ones that resolve) and applies
no `TYPE_MAP`. `@treturn void` reads `void` on the html page and `nil` in
`luadox.lua`. Any Rust implementation that shares a "format a type" helper between the
two renderers is already wrong.

> `types`: `bool int float double` → `boolean integer number number`; `Color` resolves;
> `Unknown` and `engine::Color` pass through with one diagnostic each; `string|nil` stays;
> `void` → `nil`. The html page for the same function prints `bool`, `int`, `float`,
> `double`, `void`.

## 6. Parents

`_class_parents(topref)` builds the `---@class X : …` list. Names are appended through a
helper that **drops a name equal to the class's own name and drops duplicates**, keeping
first-seen order. Sources, in this order:

1. **`@inherits`** — `topref.flags['inherits']`, every entry. The parser accumulates
   repeated `@inherits` tags and splits each on commas, so
   `@inherits A, B` + `@inherits C` yields `['A', 'B', 'C']`. The oracle also tolerates a
   bare string here for compatibility with an older shape of the flag.
   **No resolution check**: a parent that names no documented class is emitted anyway.
   (The prerender stage raises a `references` diagnostic for it, so the run still fails.)
2. **`[luals] mixin_suffix`** — when configured and `topref.name + suffix` is the name of
   a documented class, that class is added. A convention for APIs where `Foo` has a
   companion `FooMetadata` whose members are accessed as `Foo.Member`.
3. **`[luals] mixin_doc_phrase`** — when configured, every line of every `Markdown`
   fragment of the class's content that *contains* the phrase (a plain substring test) is
   scanned for `luadox:([0-9a-fA-F]+)` ids; each id that resolves to a `ClassRef`
   contributes its name, and each name that is also in the documented-class set is added.
   This reads the content **after** link resolution, so the phrase must match the prose
   as written and the references must be `@{…}` or backticked refs that resolved.

Both mixin sources require the candidate to be in `_classnames` — the names of the
`ClassRef` toprefs of this run — which `@inherits` does not.

> `inherits_multi`: `---@class Derived : Middle, Mixin, Missing`, where `Missing` exists
> nowhere. The html page for the same class lists only `Middle` and `Mixin` under
> *Inherits*.
> `luals_config`: `mixin_suffix = Metadata` and
> `mixin_doc_phrase = Inherits properties from` together give
> `---@class Widget : WidgetMetadata, Application`, `WidgetMetadata` contributed by both
> and de-duplicated.

## 7. What is deliberately not emitted

This section exists because most of it is surprising. Every item is verified by a fixture
except the one marked *unverified*.

### LS-7.1 `---@enum`

**The pinned oracle never emits `---@enum`.** An `@enum` table is a `TableRef` like any
other, so it is emitted by §3.4 as `---@class` plus one `---@type any` field per member,
each assigned `nil`. The member's literal value — which the parser captured and the html
renderer prints — is dropped.

A native `---@enum` emission exists on the fork, in commit `78ba620` *luals: emit @enum
tables as a closed ---@enum*, which is reachable from `origin/luals-tags-staging` and
`origin/pr4-review`. It is not an ancestor of the oracle. See §10.

> `enum`: `FocusScope.Hex = 0x10` in the source becomes
> ```
> ---A hexadecimal value.
> ---@type any
> FocusScope.Hex = nil
> ```

### LS-7.2 `---@deprecated`

Not emitted either. `@deprecated` reaches the output only as the admonition the prerender
stage inserts at **position 0** of the element's content, which §4.4 renders as
`**Deprecated**` followed by the explanation — *before* the element's own description.

> `deprecated_since`:
> ```
> ---**Deprecated**
> ---Use Modern instead.
> ---A legacy class.
> ---@class Legacy
> ```

### LS-7.3 `@since`

Not emitted in any form. `flags['since']` is set by the parser, read by the html renderer,
and ignored here.

### LS-7.4 Everything else that is dropped

| dropped | consequence |
|---|---|
| `@section` | sections vanish; their members are emitted inline, indistinguishable from the class's own |
| `@compact` | no effect whatsoever on this renderer |
| `@display`, `@fullnames` | names come from `name`/`symbol`; the display name is never used |
| field values | every field is `= nil` |
| `ManualRef` | manual pages produce nothing |
| an implicit module's own doc comment | lost (§3.3) |
| `@meta` on a *function* | `_emit_field` appends `*<meta>*`; `_emit_function` does not, so a function's `@meta` is dropped where the html renderer shows it (*unverified*: the fixtures only put `@meta` on a field) |

**There are no type aliases in the output at all.** The renderer emits `---@meta`,
`---@class`, `---@type`, `---@param` and `---@return`, and nothing else. `---@alias`,
`---@field`, `---@overload`, `---@generic`, `---@operator`, `---@nodiscard` and
`---@package` never appear. In particular a class's members are emitted as *assignments*
(`Widget.label = nil`) rather than as `---@field` lines on the class.

## 8. Diagnostics this renderer raises

Two categories. `types` is raised **only** by this renderer, so it never appears in an
html or json run of the same input. `untyped` is raised by the prerenderer in every run
*and* a second time here, with a different message (§8.2).

### LS-8.1 `types`

One per offending part of a type expression, at the **element's** file and line (the
`ctx` the caller set, which is the field's or function's declaration line, not the
`@tparam`'s). Two messages, verbatim:

```
type name "<part>" uses C++ scope syntax; use "."
type name "<part>" does not resolve to a documented class or table
```

### LS-8.2 `untyped`

One per parameter with no types, again at the element's line:

```
parameter "<name>" of <ref.symbol> has no documented type
```

This is raised **in addition to** the prerender stage's own
`<name>() missing @tparam for "<param>" parameter`, which fires for the same parameter in
every renderer. A luals run therefore reports the same gap twice, under the same
category, at the same line, with two different messages.

> `types`: `diagnostics-luals.json` has four entries and `diagnostics-html.json` one.
> Both runs exit 1.

The upstream `origin/pr4-review` removes the duplicate; the oracle has it. A Phase 3
implementation that emits it once is *better* and should be recorded in
`harness/improvements.toml`, not silently matched.

## 9. Unspecified, or specified only by reading the code

Honest gaps. Each is a place where the oracle's behaviour is either untested by a fixture
or genuinely undetermined.

1. **`_get_outfile` on odd paths** (§LS-1.1). A directory named `x.lua`, a `dst` that is
   an existing file with a different extension, and a `dst` whose parent does not exist
   and cannot be created are all read from the code, not exercised.
2. **The empty-implicit-module skip is believed dead.** `userdata['empty']` is
   `not has_content`, and `has_content` is true when any collection has content —
   but `parse_raw_content` appends a sentinel line to *every* collection, so
   `colref.content` is a non-empty list even for a collection with no doc comment at all.
   A module that is in `topsyms` always has at least itself as a collection, so the test
   can never be true for a module that reaches the renderer. I could not construct a
   counter-example. Keep the branch; do not rely on it.
3. **`mixin_doc_phrase` with a multi-line phrase.** The test is a substring test on one
   *line* of markdown, so a phrase spanning a wrap is never matched. Whether that is
   intended is not recorded anywhere.
4. **`@alias` and the `_classnames` set.** `_classnames` is built from topref *names*, so
   a class reachable only under its `@alias` is not a valid `mixin_suffix` candidate. Not
   exercised; the naming fixture only shows an alias resolving in a *type* position
   (§5.1 step 3 goes through `resolve_ref`, which does honour aliases).
5. **Non-ASCII.** The corpus is pure ASCII and so are the fixtures. The file is written
   as UTF-8 and content is passed through unmodified, so nothing here should mangle
   anything — untested.
6. **Ordering of `stubs` insertion relative to the globals block** (§LS-1.4).
7. **What the language server does with the output** is out of scope. The one place this
   spec asserts intent rather than behaviour is the `---@return any` fallback (§4.2), and
   the code comment there is the only record of why.

## 10. Appendix: the newer renderer on `origin/pr4-review`

The fork's PR lineage carries a LuaLS renderer that is strictly newer than the oracle's.
It is **not** what Phase 3 must reproduce, and it is recorded here only so that whoever
implements Phase 3 chooses deliberately rather than discovering it later. The delta,
which is `git diff <oracle> origin/pr4-review -- luadox/render/luals.py`:

1. **`---@deprecated`** emitted for any element with the flag, immediately after the doc
   comment. The Deprecated admonition then renders **without** its `**Deprecated**`
   title, keeping only the explanation.
2. **`--- Since <version>.`** emitted as a plain doc line for `@since`, after the
   deprecation annotation. (LuaLS has no native `@since`.)
3. **`---@enum`** for an `@enum` table, replacing the `---@class` form entirely:
   ```
   ---@enum <name>
   <name> = {
       ---<doc line>
       ---@deprecated
       <member symbol> = <value or nil>,
   }
   ```
   with four-space indentation, a trailing comma on every member, and the member's
   captured literal value.
4. `@inherits` read only as a list, the untyped double-report of §8.2 removed, and two
   line-wrap-only changes.

Adopting it changes the expected output of the `enum`, `deprecated_since` and `types`
fixtures, and it is a change to the *oracle*, not to the port: make it there first, so
the differential still compares two implementations of one specification.
